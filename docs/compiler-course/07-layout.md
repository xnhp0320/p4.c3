# 第 7 讲：输出布局 IR

[上一讲](06-values-and-memory.md) · [课程目录](README.md) · [下一讲](08-scheduling.md)

本讲目标：把“输出哪些内容”转换为区间与位置公式，并区分静态事实和运行时值。

## 1. 输出片段

一个教学输出片段可以携带这些信息：

```text
OutputPiece {
    source: OriginalRegion | ScratchRegion | GeneratedValue
    length: 常量或运行时表达式
    selected: validity 与 guard 的选择结果
}
```

片段顺序遵守 v0 固定输出顺序，条件只决定是否出现。一个 header 可以拆成多个片段，例如未修改的原字节与新字段值；能否合并，要看来源、目标和依赖是否允许。

guard 应在提交所需的正确语义时刻求值，并在任何可能破坏其来源的写入前准备好结果。不要在内存搬移后再通过失效指针重新求值。

## 2. 固定 payload 的公式

定义：

- S：原报文起点在底层缓冲区中的偏移。
- I：parser 消费的字节数。
- P = S + I：payload 起点。
- O：所有选中输出 header 片段的长度之和，不含 payload。

如果 payload 保持原位，新报文起点必须满足：

```text
S_new = P - O = S + I - O
```

这是字节布局关系。实现必须避免无符号减法下溢；若 O 大于 I，需要检查前方 headroom 是否足够，再计算新起点。

对选中的片段，依次令长度为 L0、L1 等：

```text
dst0 = S_new
dst1 = S_new + L0
dst2 = S_new + L0 + L1
```

若保留未选中项参与计算，其有效长度应视为 0，且不执行对应读取或写入。

## 3. 算例

原来 A、B、C 各 2 字节，S = 16，I = 6，因此 P = 22。删除 B 后 O = 4，得到 S_new = 18。

A 从 `[16, 18)` 移到 `[18, 20)`，C 保持 `[20, 22)`，payload 从 22 开始不变。

若在保留 A、B、C 的基础上新增一个 4 字节前缀 X，则 O = 10，S_new = 12。旧头部和 payload 可以原位保留，X 写入 `[12, 16)`，前提是该空间可用且写入依赖满足。

## 4. 编译期与运行时的分工

固定字段长度和固定输出顺序通常可以在编译期确定。validity、guard、varbit 长度可能依赖报文，在运行时才能知道。

专用代码生成不要求所有偏移都是常量。编译器可以生成简化后的运行时公式，消除不必要的通用解释过程。例如只有 B 可选时，O 可以表达为固定部分加上 B 的条件长度。

不要为 k 个独立条件直接生成全部 2 的 k 次方种路径；代码体积和分支代价也需要控制。

## 5. 布局成立与快路径可用是两回事

公式给出目标位置，并不自动保证 mbuf 可写、输入前缀连续或容量足够。项目快路径要求这些条件成立，否则要进入明确的回退。

来源顺序不兼容、无法证明连续的累计区等情况，也可能需要 scratch。只有最终计划满足来源、长度和覆盖约束，才能安全执行。

## 练习

S = 32，I = 6，payload 长度为 100。只输出 C，C 长度为 2。求 P、O、S_new 和输出总长度。为什么不能用 O 重新推算原 payload 起点？

## 参考答案

P = 38，O = 2，S_new = 36，输出总长度为 102。O 记录输出头部长度，I 记录输入消费量，删除 header 不会改变输入消费历史。用 S + O 会错误地得到位置 34。
