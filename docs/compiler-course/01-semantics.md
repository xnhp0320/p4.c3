# 第 1 讲：程序语义与物理实现

[课程目录](README.md) · [下一讲](02-semantic-analysis.md)

本讲目标：能把“应该输出什么”与“用什么内存操作实现”分开，并解释 parser 消费终点为什么必须单独记录。

## 1. 什么叫编译正确

编译器把程序转换成另一种表示。转换前后的内部步骤可以不同，但约定的可观察行为必须一致。最初的报文练习关注两个结果：是否 reject，以及成功时输出的字节序列。接入运行时后，还需要定义其他可观察状态和失败接口。

例如，源程序让 B 无效，并不要求生成代码擦除 B 占用的内存。只要输出不再包含 B，且没有破坏后续所需的值，就可以采用调整起点等实现。

注意 invalid header 的 emit 是 no-op，而“删除 header”只是我们对这一效果的口语描述。

## 2. 贯穿案例

输入如下，parser 依次提取 A、B、C：

```text
[A：2 字节][B：2 字节][C：2 字节][payload：4 字节]
```

parser 消费了 6 字节，剩余 4 字节是 payload。让 B 无效，按 A、B、C 的顺序 emit，得到：

```text
[A][C][payload]
```

参考模型可以申请新缓冲区，依次追加 A、C、payload。这样的实现容易检查，可以用于检验更复杂的优化。

固定 payload 的另一种实现是：

| 内容 | 原始区间 | 输出区间 |
| --- | --- | --- |
| A | `[0, 2)` | `[2, 4)` |
| B | `[2, 4)` | 不输出 |
| C | `[4, 6)` | `[4, 6)` |
| payload | `[6, 10)` | `[6, 10)` |

只需把 A 搬到位置 2，再把报文起点调整到位置 2，长度设为 8。逻辑上删除 B，物理上移动的是 A。

这里假设提交时 B 的旧字节已不再需要。若还有计算要读取它，就必须先完成读取或保存其值。

## 3. 消费终点与有效长度

parser 的 cursor 表示已经消费多少输入。header validity 表示某个逻辑实例当前是否有效，两者描述不同事实。

即使把 A、B 都设为无效，cursor 仍然是 6。payload 仍从位置 6 开始，不能因为只剩一个 2 字节的有效 header，就把位置 2 当成 payload 起点。

循环会进一步放大这个区别：连续两次 extract 到同一个实例时，该实例保留最后一次提取的值，但 cursor 包含两次消费量。较早消费的字节不会自动成为 payload。

## 4. 对 IR 的启发

语义层先表达“输出 A 当前内容、输出 C 当前内容、追加剩余 payload”。布局层再决定输出位置，执行层决定移动和写入。

“当前内容”很重要。如果 A 被修改，原输入区间不一定代表 A 的当前值。把每个 header 永远绑定为原报文指针，会丢失这种区别。

## 练习

1. 原例中 A、B 都无效，只输出 C 和 payload。输出长度、新起点和需要搬移的字节数分别是多少？
2. 此时 cursor 是否变化？
3. 一个 2 字节的实例 H 连续提取两次，输入为 `11 22 33 44 aa bb`，之后只 emit H。输出是什么？

## 参考答案

1. 长度 6，新起点为原位置 4，搬移 0 字节。C 和 payload 已经相邻。
2. cursor 仍是 6；改变 validity 不会撤销已发生的输入消费。
3. 输出为 `33 44 aa bb`。H 保留第二次提取内容，payload 从位置 4 开始。`11 22` 已消费且未输出。

掌握标准：能不用 memcpy、指针等术语，先准确描述一个例子的输出，再给出一种物理实现。
