# 第 10 讲：正确性验证与性能实验

[上一讲](09-codegen.md) · [课程目录](README.md)

本讲目标：定位编译阶段错误，并通过可复现的实验判断优化收益。

## 1. 三个检查层次

| 层次 | 例子 | 发现的问题 |
| --- | --- | --- |
| IR 验证 | ID、类型、控制流目标是否合法 | 表示的结构错误 |
| 语义差分 | 同程序同输入比较输出 | 行为不一致 |
| 内存与运行时检查 | 哨兵、sanitizer、容量边界 | 越界或接口错误 |

三者不能互相替代。输出正确也可能越界；合法 IR 也可能来自错误 lowering。

## 2. 使用参考解释器

已有 [interp.c3](../../src/interp.c3) 和 [refmodel_test.c3](../../test/refmodel_test.c3) 可以作为对照入口。

同一受支持程序和输入交给参考模型与待测实现，成功时逐字节比较输出和长度，源程序拒绝时比较拒绝行为。资源不足与工具超时应单独分类。

参考模型也可能有 bug，共享前端可能产生共同错误。保留独立手算的小例子，不能把两个结果一致当成数学证明。

## 3. 分阶段定位

提供语义 IR、输出片段、布局和计划的 dump。还可以为执行计划写一个在带边界检查的字节数组上运行的模拟器。

依次检查：输出内容选择是否正确？来源和长度是否正确？目的位置是否正确？顺序是否保护旧值？生成 C 是否忠实执行计划？

计划模拟正确而 C 错误时，优先查后端与运行时；输出片段已经错误时，不应先调 memmove 顺序。

## 4. 测试矩阵

| 维度 | 起步用例 |
| --- | --- |
| 布局 | 原样、前缀增删、中间增删 |
| 条件 | 有效/无效、guard 真/假、组合选择 |
| 长度 | 最小包、恰好足够、差一个字节、允许处的零长度 |
| Parser | 分支、循环提取、循环中途短包 |
| 来源 | 原报文、修改字段、scratch、非连续 extract_end |
| 环境 | headroom 足够/不足、共享缓冲、多段输入 |

随机测试应生成子集内合法程序，非法程序作为诊断测试单独处理。失败时保存种子、程序、报文、目标条件与阶段 dump，再缩减为稳定复现的最小例子。

## 5. 可比的性能实验

与手写 C 对比时，保持相同报文行为、错误处理范围、输入分布和运行条件。记录编译器及选项、硬件、包长、条件分布和重复测量结果。

至少观察 cycles/packet 与复制字节数。复制量应定义口径，例如各次复制/移动调用长度之和，新字段写入另行统计。它不是总内存流量，也不能替代时间测量。

少复制不一定更快，分支、ctx 访问、临时存储和代码体积可能抵消收益。报告重复测量的分布，避免只选最好的一次。

## 6. 毕业练习

按顺序设计四个可验证闭环：

1. 固定 header 的保守 gather 输出，与参考模型比较。
2. 原样转发路径，证明何时无需复制。
3. 前缀删除和插入，验证起点、长度和容量。
4. 中间增删，生成依赖安全的前缀移动计划。

每步写出输入限制、IR 不变量、回退条件、正反例和测量方案。一次增加一种优化类别，便于定位问题。

## 练习

输出与参考模型一致，但写坏了输入尾部的哨兵字节，算通过吗？两个实现产生相同错误输出又该怎么办？

## 参考答案

前者不通过，字节输出正确不代表内存安全。后者可能是共同错误，需要借助手算期望、独立语义用例或其他可信对照定位。
