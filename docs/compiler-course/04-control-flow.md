# 第 4 讲：控制流与循环

[上一讲](03-ir-design.md) · [课程目录](README.md) · [下一讲](05-dataflow.md)

本讲目标：能够把 parser 状态转换为控制流图，并理解循环为什么需要迭代分析。

## 1. 基本块与控制流图

基本块是一段内部没有分支跳转的顺序操作，控制从入口进入，经过末尾的终结操作离开。终结操作可以是无条件跳转、条件跳转、接受或拒绝。

控制流图 CFG（Control Flow Graph）用节点表示块、边表示可能的执行转移。例如：

```text
start: 提取 A
    条件成立 -> with_b
    否则     -> finish

with_b: 提取 B
    -> finish

finish:
    -> accept
```

finish 有两个前驱，因此它不能假定 B 一定被提取过。一个 parser state 可以是构造 CFG 的起点，但若提取的失败边等控制效果被显式展开，一个 state 可能对应多个基本块。

## 2. 隐藏的失败边

提取操作可能遇到短包。IR 可以把 Extract 定义为带失败效果的高层操作，也可以将它降低为“检查、读取、推进 cursor”几个步骤。

无论选择哪一种，分析和代码生成都不能忽略失败行为。若只画正常 transition，得到的是不完整的执行模型。

```text
check_remaining(n)
    足够 -> extract_body
    不足 -> reject
```

在后端中，先证明 cursor 不超过输入长度，再比较 `n <= input_len - cursor`，可以避免直接计算 `cursor + n` 导致的溢出风险。

## 3. 回边不等于可以展开

一个状态再次跳回自己或更早的状态，会形成循环。例如 TLV 解析不断读取下一项，直到遇到终止标记。

循环次数可能依赖报文字节，不能因为源码中只有一个 Extract 就认为运行时只提取一次。对固定宽度、每轮确实消费输入的循环，报文长度会限制成功迭代次数；但边界检查本身并不能保证所有循环终止，零消费循环就是反例。

v0 允许 parser 回边。优化不能通过随意截断迭代次数改变行为；测试工具若设执行预算，应把预算耗尽与正常 reject 区分。

## 4. 支配关系和 SSA 的入门含义

若从入口到块 B 的每条路径都经过块 A，就说 A 支配 B。它有助于判断一个值的定义是否一定先于使用。

SSA（静态单赋值）给每个定义唯一的值名。分支合并处使用 phi 表达“根据实际前驱选值”：

```text
left:  x1 = 10
right: x2 = 20
join:  x3 = phi(left: x1, right: x2)
```

phi 不是把两个值相加，也不是无条件同时求值。它表达沿哪个前驱到达，就取哪个输入。初期可以先使用显式状态变量，不必立即建立完整 SSA；但理解值版本对后续来源分析有帮助。

## 练习

1. 在本讲的 start / with_b / finish 例子中，with_b 是否支配 finish？start 是否支配 finish？
2. 如果循环每轮 extract 到同一个 H，H 在循环出口是否代表第一次提取？
3. “每次 extract 都检查剩余长度，所以所有 parser 都会终止”为什么不成立？

## 参考答案

1. with_b 不支配 finish，因为存在直接到 finish 的路径；start 支配 finish。
2. 在至少一次成功提取并正常退出的路径上，H 代表最后一次提取。零次迭代路径还要考虑进入循环前的状态。
3. 循环可能没有 extract，或没有正的 cursor 增量。边界检查解决读取安全，不自动证明控制流终止。
